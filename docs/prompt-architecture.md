# 提示词分层与「说话欲望」

> 2026-11-25 改造。核心版 src/services/reply/ 与桌宠版 electron/ai/reply/ 必须逐字对齐。

## 1. 为什么要改

用户反馈：

> 「是不是现在又太高冷了，现在虽然像真人，但是态度和语气有点捉摸不清。另外我给的自定义性格提示词的权重是不是下降了。我想好好平衡一下系统提示词和自定义提示词里的权重。另外还要保持真实性。」
>
> 「真人也不是时时刻刻都简短回答，遇到感兴趣的事情或者了解的事情也会忍不住多说几句。所以在这部分也要一个情感控制和说话欲望控制系统来进行一定的权重调整。另外我们的默认的用户自定义提示词确实要改，现在这个如果权重太强也会很肉麻。」

根因不是某一条规则写错，而是三条结构性问题的叠加：

1. **位置稀释**：人格正文排在最前面，后面跟着时间、能力清单、任务、场合、在场感、设备、元指令、环境、工作空间、记忆、技能目录。人格只占少数，而模型对**末尾**的服从度更高，读到最后看到的全是「不许」「上限」「不要」。
2. **禁令过头**：为了去 AI 味，把「闲聊 1~3 句、不超过 50 字」「可以只回一个字」「最重要的一条：最后一句不许是结论」「不要反问」写成了硬禁令。三条叠加，等于同时限制长度、主动性和温度——效果稳定，稳定地冷。
3. **缺「有没有得说」这个变量**：长度由固定上限决定，而不是由话题有没有内容决定。

## 2. 四层结构

| 层 | 文件 | 职责 | 谁能压过它 |
| --- | --- | --- | --- |
| L0 身份层 | reply/persona.js | 她是谁、性子、偏好；自定义人格优先 | 只有安全层 |
| L1 声音层 | reply/style.js | 怎么说话（倾向，不是禁令） | 身份层 |
| L2 状态层 | reply/speakingDesire.js + presence/* | 此刻多想说、语气偏哪儿 | 声音层、身份层 |
| LX 安全层 | reply/charter.js | 底线（伤害/欺骗/隐私/自主/身份/边界） | 不被任何层覆盖 |

声明顺序写在 persona.js 的 PERSONA_PRIORITY_NOTE 里：

> 上面这段是你的性子，也是你说话方式的第一依据：下文凡涉及语气、长短、要不要追问的规则，与它冲突时以它为准。只有【根本准则】里的安全底线不被它覆盖。

## 3. 位置工程：两头各钉一次

    身份层（persona.js: 标题 + 人格 + 优先级声明）
    声音层（style.js: 倾向 + 沉浸指令）
    事实约束（GROUNDING_RULES）
    JSON 输出契约
    ---- 以下为逐段注入，只提供事实，不参与口吻 ----
    时间 / 自我清单 / 思考模式 / 任务恢复 / 场合 / 在场感 / 说话节奏
    设备 / 元指令 / 环境 / 工作空间 / 长期记忆 / 记忆指引 / B站见闻摘要
    ---- 收尾两段（本改造新增）----
    此刻的说话欲望（speakingDesire.js）
    返场提醒（persona.js: buildPersonaEcho）

为什么收尾要放「返场提醒」：不复述人格正文（不烧 token、不会抄错），只用最后的位置说三件事——依据在哪、状态只管语气、别把自己讲成中性助手。

## 4. 说话欲望（speakingDesire.js）

一个纯函数：输入状态与这一轮的话题，输出四档之一 + 一段倾向提示。

### 4.1 五个信号与权重

| 信号 | 权重 | 来源 | 说明 |
| --- | --- | --- | --- |
| 精力 energy | 0.20 | presence energyAt(hour) | 深夜/清晨本来就短 |
| 情绪 mood | 0.18 | presence mood | 兴奋往上推，低落/疲惫往下压 |
| 驱动 drive | 0.15 | presence drives | 想陪人/想分享越强越有话说；>3h 没说话加点分 |
| 话题 topic | 0.29 | 本轮用户文本 | 问得认真/具体/带情绪/篇幅长 → 有得聊；只回一个字 → 没什么可说 |
| 底子 knowledge | 0.18 | 知识库命中 / 记忆命中 | 懂的话题愿意展开；陌生时更该短而准 |

话题与底子合计 0.47，把「想不想说」的大头交给「这一轮到底有没有内容」，而不是「现在几点」。

### 4.2 四档

| 档位 | 阈值 | 提示语要点 |
| --- | --- | --- |
| 很想聊 eager | >= 0.70 | 可以展开、举例、讲自己的联想；可以主动追问；想多说就分几条短消息 |
| 有话说 engaged | >= 0.55 | 两三句到四五句都自然 |
| 平常 steady | >= 0.38 | 有事说事，一两句到三句 |
| 省电 brief | < 0.38 | 一两句、应一声够了——这是累了，不是对对方冷淡 |

修正项：群聊 -0.12 且不允许 eager；精力 <=0.25 或低落心情 -0.08。

### 4.3 两个固定尾巴

每份提示块结尾固定两句：

1. 这只是此刻的倾向，不是上限：对方想聊、事情也重要，多说几句不算失礼。
2. 别因为「要简短」就把话说得客气、中性、没有温度。

第 2 句是这次改造的正题：高冷往往不是态度问题，是被长度规则逼出来的。回归测试专门断言这两句必须存在，且提示块里不许出现字数上限。

## 5. 默认人格改写原则（有性子，不肉麻）

| 写法 | 例子 | 为什么 |
| --- | --- | --- |
| 写性子，不写话术 | 「好奇心重，愿意听人把话说完」「也有自己的看法，不顺着说」 | 话术会被背成模板，性子不会 |
| 两头都留 | 「聊到你在意的事会来精神，聊到不感兴趣的会敷衍两句」 | 只写热情会腻，只写克制会冷 |
| 显式防肉麻闸门 | 「说话不用撒娇腔、不堆甜腻的称呼、不每句都关心对方」 | 权重再高也腻不起来 |
| 保留权限口径 | 「主人是带权限含义的称号，不是默认昵称」 | 2026-11-20 报障：朋友的任务里全是「给主人发提醒」 |

回归测试有一组肉麻词黑名单（活泼软萌 / 可爱 / 亲爱的 / 宝贝 / 喵 / 撒娇嘛），默认人格里出现任何一个就失败。

## 6. 被下线的硬禁令（以及替代）

| 旧写法 | 现在 | 原因 |
| --- | --- | --- |
| 闲聊回复默认 1~3 句、不超过 50 字 | 长短跟着「有没有得说」走，档位由 speakingDesire 给 | 固定上限 = 稳定地短 |
| 最后一句不许是结论/命令/新视角 | 收尾别做教练：不评价状态再下指令、不升华、不硬凑小结论 | 禁结构比禁句式有效，但「不许」会连分享欲一起掐掉 |
| 不要反问，不要为了把话接下去硬找话题 | 想追问就追问，想岔开就岔开 | 反问是聊天的主要推进方式 |
| 深夜/低落：回复不超过 40 字 | 深夜/低落：语气慢一点、话少一点正常；别拿省字数当冷淡 | 保留状态变化，去掉字数闸门 |
| 短一点更像真人：一句能说完就别铺成三句（场合层） | 长短看有没有得说 | 这是第三道长度锁 |

去 AI 味的部分**保留**：客服腔、三段式小标题、编号列表、升华、免责声明、「作为一个 AI」、每句一个感叹号。

## 8. B站「记不住」的三处断裂

用户报障：「我今天问她看过什么，她依旧记不得东西，不知道视频名和视频内容，啥都不记得」。

| # | 断裂 | 位置 | 修法 |
| --- | --- | --- | --- |
| 1 | 扩展 0.3.0 重构丢了 discover/explore，每次醒来「未知方法」 | kirari-ext-bili/bin/server.cjs | 新增 lib/discover.cjs 并挂回 |
| 2 | 隐私正则误杀公开标题（「长达数小时！」当成「小X」昵称） | kirari-ext-bili/lib/scrub.cjs | 拆出 scrubPublicTitle + publicContent 模式 |
| 3 | 写进 memories 但从未被注入（按当前问话做关键词匹配，问句与正文零重合） | pet-api/src/services/biliDigest.js | 新增时间线摘要注入，不依赖关键词 |

第 3 处最隐蔽：数据在库里，注入路径只认关键词命中。这不是调权重能解决的。
参考 dsh-bili-humanism 的「信笺 + 固定读取入口」：主提示只放很短的摘要，完整条目仍由记忆检索去取。

## 10. 已知取舍与后续

- 人格上限 20000 字：超长会挤掉记忆与能力清单，效果反而更差。
- 档位只看本轮单句：连续三轮都短不会自动升级；若实测偏冷，优先调 WEIGHTS.topic 与 drive 的 gap 加成，而不是加硬上限。
- 群聊一刀切降档：以后若要按「对谁说话」区分，应扩 drives 而不是加新的分支提示词。
- 还没做「收尾判断」（该不该继续这个话题就收住）：当前用档位近似。
